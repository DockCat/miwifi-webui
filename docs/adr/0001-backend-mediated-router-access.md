# ADR 0001 — Backend-mediated Router Access

Status: `ACCEPTED`

Date: `2026-09-04`

## Context

`miwifi-webui` manages routers that expose local MiWiFi Web APIs.

Those APIs require sensitive router authentication material and may expose session tokens such as `stok`.

Direct browser-to-router communication would create several problems:

* router credentials/session material would enter the browser trust boundary;
* CORS/browser Local Network Access restrictions could vary by browser;
* logging/redaction would become harder to centralize;
* API normalization would leak into UI code;
* router compatibility probing would be fragmented;
* router operations would be harder to audit consistently;
* router sessions would be difficult to manage reliably.

The application needs a stable boundary around router-specific behavior.

## Decision

All Xiaomi router access must be mediated by the application backend.

Accepted flow:

```text
Browser
   |
   v
Backend
   |
   v
MiWifiAdapter
   |
   v
Xiaomi Router
```

The browser must not directly call MiWiFi router endpoints.

Router authentication, session management, capability detection, API request construction, response normalization, polling, and router mutations belong to the backend.

Router passwords and `stok` must remain backend-only.

## Rationale

This approach provides:

* a clear security boundary;
* central secret handling;
* consistent audit behavior;
* testable router abstraction;
* browser-independent router access;
* centralized compatibility logic;
* one place to classify router operation effects.

It also prevents frontend implementation from becoming coupled to undocumented/model-specific endpoint details.

## Consequences

### Positive

* frontend cannot accidentally expose `stok`;
* router API variations can be normalized;
* router calls can be mocked in tests;
* logging/redaction can be centralized;
* browser CORS/local-network restrictions are avoided for router APIs;
* router-session renewal is centrally managed.

### Negative

* backend must be able to reach the router's LAN address;
* deployment topology is more important;
* backend becomes a sensitive network actor;
* SSRF/target-validation protections are required.

## Security consequences

Router onboarding must not turn the backend into an arbitrary URL fetcher.

Router hosts must be validated.

API endpoint paths should be generated by the adapter.

Redirect behavior must not silently bypass target validation.

## Alternatives considered

### Browser directly accesses router

Rejected.

This would leak router trust into browser code and depend on variable browser/local-network policies.

### Hybrid browser/backend router access

Rejected.

Two router-access paths would duplicate authentication, auditing, error handling, and capability logic.

## Revisit when

Reconsider only if Xiaomi provides a new officially supported architecture that removes router secrets from browser interactions and offers a secure stable browser API.

Even then, the audit/integration benefits of backend mediation must be reconsidered before changing this boundary.
